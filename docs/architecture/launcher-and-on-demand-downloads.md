# Launcher & On-Demand ROM Downloads Architecture

## 1. Overview

`romm-steam-sync-launcher` is a lightweight wrapper executable/script that acts as the target binary for all Steam non-Steam shortcuts generated by `romm-steam-sync`.

### Standalone Executable Packaging & Wrapper Installation
To eliminate any requirement for users to have a system Python interpreter installed:
- **Packaged Standalone Executables**: Built with PyInstaller as native binaries (`romm-steam-sync-launcher.exe` on Windows, native ELF executable `romm-steam-sync-launcher` on Linux).
- **Automatic Wrapper Installation (`adapters/wrapper_installer.py`)**:
  - When `romm-steam-sync` starts or synchronizes libraries, `install_wrapper()` copies the bundled launcher executable into the user configuration directory (`%APPDATA%\romm-steam-sync\bin\` on Windows, `~/.config/romm-steam-sync/bin/` on Linux).
  - **Platform Magic-Byte Guard (`_is_platform_native_binary`)**: Inspects binary header bytes (`MZ` for Windows PE executables, `\x7fELF` for Linux/macOS ELF binaries). This ensures that if a wrong-platform binary is bundled during cross-compilation or testing, it is rejected immediately rather than installed and triggering an `Exec format error`.
- **Development Script Fallbacks**:
  - **Windows**: Generates `romm-steam-sync-launcher.vbs` executed silently by Windows Script Host (`wscript.exe`) calling `pythonw.exe`. This prevents console windows or command prompts from flashing when launching games. Subprocess spawning of RetroArch uses `creationflags=subprocess.CREATE_NO_WINDOW`.
  - **macOS / Linux**: Generates an executable shell script `romm-steam-sync-launcher`.

When a user clicks **Play** on a RomM shortcut in Steam, Steam executes `romm-steam-sync-launcher`. The launcher intercepts execution to handle:
1. **Interactive Version / Disc Selection** for multi-version sibling groups.
2. **On-Demand ROM Downloading & Extraction** if the game file is not yet on local disk.
3. **Pre-Launch Save File Synchronization** from RomM.
4. **RetroArch Execution** with the resolved flavor, libretro core, and window foregrounding.
5. **Post-Launch Save Synchronization & Playtime Recording** upon process exit.

## 2.1 Multi-Version & Multi-Disc Game Launching

When launching a game that contains multiple versions, regional variants, or discs:
1. **Inspection**: The launcher checks SQLite DB and RomM API for all sibling ROMs linked to the game's `sibling_group_key`.
2. **Default Preference Evaluation**: If the user previously selected **"Always run this version for this game"**, the selection is stored in SQLite `kv_config` (`default_version:<sibling_group_key>`). The launcher automatically loads the preferred version and bypasses the selection dialog.
3. **Interactive Version Selection Modal**: If no preference is set, the launcher presents an interactive selection screen (`640x540`):
   - **Card Titles**: Distinguishing ROM filenames and tags (e.g. `Dark Cloud 2 (USA) (v1.00)`, `Dark Cloud 2 (USA) (v2.00)`, `Dark Cloud 2 (Europe)`).
   - **Metadata Subtitles**: Badges showing Region, Version/Revision, Disc, Languages, and File Size.
   - **Install Badges**: Plain text `"Installed"` vs `"RomM Cloud"` badges indicating local availability.
   - **Preference Checkbox**: Selecting `[x] Always run this version for this game` persists the preference to SQLite `kv_config`.
4. **Standard Execution**: Once a version is selected, execution proceeds to local file verification, on-demand downloading, save sync, and RetroArch launching.

## 3. On-Demand ROM Downloading & Archive Extraction

### Rationale
Allowing shortcuts to exist in Steam before ROM files are downloaded locally enables users to browse their full RomM library in Steam without taking up disk space for games they haven't played yet.

### Download & Extraction Mechanics
- If `romm-steam-sync-launcher` detects that `rom_installs.file_path` does not exist on disk:
  1. The launcher opens a native dialog or OS notification showing smoothed download progress (`Downloading Super Mario World... 45%`).
  2. Connects to RomM `/api/roms/{id}/content` to download the ROM archive/file into the configured local platform ROM folder (`<library_dir>/<platform_slug>/`).
  3. **Archive Extraction (`adapters/archive_extractor.py`)**: If the downloaded file is a compressed archive (`.zip`, `.7z`, `.tar`, `.rar`) and the target core requires uncompressed files, it unpacks the archive, verifies the primary launchable ROM file, and records the extracted path.
  4. Updates the `rom_installs` SQLite record with `file_path`, `rom_dir`, and `installed_at`.
  5. Proceeds to launching RetroArch.

### Desktop GUI Library View Integration
- **Direct Launch**: In the application **Library** tab, clicking **Launch Game** spawns `romm-steam-sync-launcher --rom-id <id> --platform <slug>` in a background subprocess, executing the identical pre/post save-sync and RetroArch launch workflow as Steam.
- **Local Uninstallation**: Clicking **Uninstall ROM** prompts confirmation, deletes the physical ROM file from local storage (`<library_dir>/<platform_slug>/<filename>`), and removes its tracking record from SQLite `rom_installs`. Saved games and Steam shortcut bindings remain intact.

## 4. RetroArch Flavor Selection & Launch Execution

Rather than relying on hardcoded system paths, `romm-steam-sync-launcher` integrates with the multi-flavor RetroArch architecture documented in [RetroArch Multi-Flavor Architecture](retroarch-flavors-and-paths.md).

### Dynamic Flavor & Core Resolution
1. Resolves active RetroArch flavor adapter via `detect_retroarch_flavor(configured_path, preferred_flavor)`:
   - **Steam**: Steam Store release in `steamapps/common/RetroArch/`.
   - **Standalone**: Local installation, OS package, or official Flatpak `org.libretro.RetroArch`.
   - **RetroDECK**: Flatpak container `net.retrodeck.retrodeck`.
2. Locates the target libretro core using `RetroArchPathResolver.resolve_core_path(core_name)` or prioritizes candidate cores from `PLATFORM_CORE_CANDIDATES`.
3. Queries `RetroArchConfigAdapter` to identify exact runtime save directories based on `retroarch.cfg`.
